# 知识库检索：从关键词到向量

## 现在的实现

`app/retrieval.py` 提供统一的向量检索接口，`app/tcm.py` 在其上做**混合检索**：

```
精确关键词命中  +  向量相似度召回  →  系统过滤（domain）→ 排序
```

- 精确命中：原有 `symptom_keys` 匹配，保证"板蓝根"这类明确说法不会丢；
- 向量召回：把整条知识库条目（药名 + 症状键 + 主治 + 证型 + 注意事项）编码成向量，按余弦相似度召回；
- 系统过滤：前面建立的症状本体，排除"感冒药里带头痛"这类跨系统误召回；
- 排序分数：`精确命中数 + 2.5 × 向量相似度`，同分时便宜的药优先。

## 默认向量器：本地 TF-IDF（字符 n-gram）

- 无需联网、无需下载模型；
- 对中文口语（"脑袋昏昏沉沉"→头晕类、"腰膝发软"→腰肾类）有实际召回效果；
- 138 条知识库，索引在内存里构建，毫秒级。

## 可选：真正的句向量模型

设置环境变量指向**本地** sentence-transformers 模型目录即可自动切换：

```bash
pip install sentence-transformers
# 例如把 bge-small-zh-v1.5 下载到 /opt/models/bge-small-zh
sudo systemctl edit health-panel.service
# [Service]
# Environment=EMBEDDING_MODEL_PATH=/opt/models/bge-small-zh
sudo systemctl restart health-panel.service
```

代码会自动用模型编码知识库与查询，其余流程不变。

> 当前机器访问不了 HuggingFace / ModelScope，因此默认走 TF-IDF；把模型放到本地路径就能切真 embedding。

## 实测（TF-IDF 模式）

| 输入 | 召回结果 |
|---|---|
| 脑袋昏昏沉沉 | 养血清脑颗粒、安神补脑液、杞菊地黄丸 |
| 小便刺痛 | 缩泉丸、乌药 |
| 皮肤起风团 | 湿毒清胶囊、当归苦参丸、地肤子 |
| 腰膝发软 | 独活寄生丸、舒筋活血片、杜仲 |
| 肚子绞着疼 | 胃苏颗粒、气滞胃痛颗粒、白芍 |

每个结果都会带 3–4 个该系统的追问问题。

## 局限

- TF-IDF 是"字面向量"，不是神经语义向量；同义改写很强时仍可能弱；
- 知识库只有 138 条，向量空间稀疏；
- 食物库检索仍是关键词匹配，可复用同一接口扩展；
- 换真模型后需要重新建索引（首次请求自动构建）。
