# 演示视频脚本（4 分钟，突出多 Agent 优势）

> 目标：让评委在 4 分钟内看懂"多 Agent ≠ 一个模型多说几句话"。
> 形式：录屏 + 旁白 + 少量字幕；不需要真人出镜。
> 工具：Windows 自带 Xbox Game Bar（Win+G）或 OBS；分辨率 1920×1080；浏览器缩放 100%。

## 分镜总览

| 时间 | 画面 | 核心信息 |
|---|---|---|
| 0:00–0:20 | 标题 + 首页 | 问题：健康建议不可信 |
| 0:20–1:10 | 问诊 + 轨迹展开 | 一支团队在工作 |
| 1:10–1:55 | 对比实验 + 消融实验 | 有数字的差异 |
| 1:55–2:25 | 安全审查注入演示 | 审查不是摆设 |
| 2:25–3:10 | 心理 + 食物识别 | 多入口、多工具 |
| 3:10–3:40 | 我的药 + 康复计划 | 从建议到行为 |
| 3:40–4:00 | 总结 + 架构图 | 可信、可解释、可复现 |

---

## 0:00–0:20 开场：问题不在"会不会说"

**画面**：黑底白字标题「健康助手：一支会查、会审、会解释的 Agent 团队」，淡入首页。

**旁白**：
> 身体不舒服时，通用大模型能立刻给出一段建议——但你不知道它查了什么、依据在哪、有没有人把关。健康场景里，这三件事比"说得像不像医生"更重要。

**字幕**：来源不可核验 · 安全边界缺失 · 过程不可解释

---

## 0:20–1:10 主流程：看着团队一步步工作

**操作**：
1. 输入：`发烧，咽喉痛，有点怕冷，两天了`
2. 发送后，用鼠标沿步骤条缓慢划过：红旗分诊 → 辨证 → 中成药匹配 → 并行取证 → 工具调用 → 安全审查；
3. 回答出现后，停留 3 秒，让"首选中药 + 来源数量 + 安全提示"入镜；
4. 点开 **轨迹**，缓慢滚动，让每一步的 Agent 名称、耗时、证据数入镜；在"并行检索"处停留。

**旁白**：
> 这一句话进来，先由路由 Agent 判断是问诊；分诊 Agent 排除红旗；辨证 Agent 判断寒热、决定要不要追问；知识库 Agent 在 138 条中药里匹配候选；并行检索 Agent 同时查 PubMed、openFDA 和 NHS/WHO/CDC；撰写 Agent 汇总；最后安全审查 Agent 检查引用、剂量、禁忌和免责声明。
>
> 注意这里：三路检索是并发的，任何一路失败都不影响整体，轨迹里会标出来。这不是一个模型"假装想过"，而是真的分工、真的调工具、真的留痕。

**字幕**：8 个环节 · 并行取证 · 引用锚定 · 全程可追溯

---

## 1:10–1:55 对比实验：用数字说话

**操作**：打开 **对比实验**，镜头依次对准四行指标：引用可核验率、审查问题数、免责声明、token/耗时。

**旁白**：
> 我们做了 4 个用例的单 Agent 对照。单 Agent 平均 5 秒、676 token，但引用可核验率是 0——它没有来源清单，说的引用无法核验；安全审查平均 4.25 个问题，4 个回答没有一个带免责声明。
>
> 多 Agent 平均 49 秒、约 1 万 token，慢十倍、贵十几倍；换来的是引用可核验率 100%，审查问题 0，免责声明 4/4。健康场景，我们认为这个交换值得，而且可以用缓存和本地 Mock 把演示成本压下来。

**操作**：切到 **消融实验**。

**旁白**：
> 每个 Agent 是不是必需？去掉知识库，可选药物从 7 个变成 0，检索再强也没有药可推荐；去掉并行检索，耗时从 1.6 秒涨到 4 秒，差不多翻倍；去掉安全审查，模板路径看不出差别——所以我们用注入测试来验证它。

**字幕**：消融：知识库不可省 · 并行不可省 · 审查需注入验证

---

## 1:55–2:25 安全审查：抓一条故意写错的剂量

**操作**：打开 **消融实验** 弹窗，展示"干净报告 0 问题 / 注入后 1 个问题"，放大被抓住的那行：

`剂量信息缺少引用：布洛芬一次 800 mg，每天 4 次`

**旁白**：
> 这是我们往报告里注入的一条错误：布洛芬一次 800 毫克、一天 4 次，还写着"不用看说明书"。审查 Agent 抓到了——剂量没有引用。真实模型写错剂量时，这条规则同样会拦下来。

**字幕**：审查不是流程装饰，是最后一道闸

---

## 2:25–3:10 多入口：情绪与饮食

**操作**：新会话输入 `最近压力大，睡不着，脑子停不下来`。

**旁白**：
> 情绪问题走心理入口，给的是可执行建议和求助资源；如果识别到高风险表达，会直接给热线和就医提示，不继续讲道理。

**操作**：点 📷，上传一张坚果图。

**旁白**：
> 食物图片走本地 CLIP，不传云端，判断健康还是垃圾食品，给出热量、营养、益处和风险。

**字幕**：一个入口一个 Agent · 工具按需加载

---

## 3:10–3:40 从建议到行为

**操作**：
1. 打开 **我的药**，点"打卡一次"，龙珠点亮、库存 -1；
2. 打开 **康复计划**，展示评分滑杆与趋势曲线。

**旁白**：
> 建议不是终点。药可以设置提醒、疗程打卡、看库存和有效期；康复计划每天打分，第 7 天根据趋势决定是延长一周还是建议复诊。

---

## 3:40–4:00 收尾

**画面**：架构图（路由 → 分诊 → 辨证 → 知识库 → 并行检索 → 撰写 → 审查 → 修复），右下角小字：`68 项测试 · 本地运行 · 断网可演示`。

**旁白**：
> 我们做的不是更会聊天的机器人，而是一支能查、能审、能解释、能落地到行为的团队。每个结论有来源，每个回答过审查，每一步可复盘。

**字幕**：可信 · 可解释 · 可复现

---

## 录制清单

- 录前：个人资料 → **重置演示数据**；模型选 **Mock**；关闭无关通知；
- 每个镜头单独录，最后剪；失败重录只重录该镜头；
- 鼠标移动放慢，点击前停顿 0.3 秒；
- 旁白先录音再对画面，或边说边录（语速约 240 字/分钟）；
- 导出 1080p MP4，文件名 `健康助手-多Agent演示.mp4`。
