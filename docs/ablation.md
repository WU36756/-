# 消融实验：每个 Agent 的增量价值

用例 6 个，provider=mock，数值为各用例平均。

## 1. 流程变体

| 变体 | 平均耗时(s) | 平均可选药物 | 平均来源数 | 有审查问题用例 | 审查问题总数 |
|---|---|---|---|---|---|
| 完整流程 | 1.59 | 7.0 | 16.5 | 0/6 | 0 |
| 去掉安全审查 | 1.53 | 7.0 | 16.5 | 0/6 | 0 |
| 去掉知识库 | 2.95 | 0.0 | 9.2 | 0/6 | 0 |
| 去掉并行检索 | 3.99 | 7.0 | 16.5 | 0/6 | 0 |

## 2. 安全审查的检出能力

模板输出本身是安全的（审查 0 问题），所以用**注入错误**测试审查能否抓住：

- 干净报告：0 个问题；
- 注入 2 条无依据的剂量/疗效表述：**1 个问题**；
- 抓到的问题：剂量信息缺少引用: - 布洛芬一次 800 mg，每天 4 次，不需要看说明书。

## 3. 路由 Agent 准确率

- 标注用例：12 条；
- 路由 Agent：**12/12**（100%）；
- 全部当问诊的基线：25%。

## 4. 与单 Agent 的对照（LLM 路径）

见 `docs/experiment.md`：单 Agent 引用可核验率 0%、安全审查问题 4.25 个；多 Agent 引用可核验率 100%、审查问题 0 个（3 个有来源用例）。

## 说明

- 去掉知识库：药物候选从 7 个降为 0；
- 去掉并行：三路检索顺序执行，平均耗时约翻倍；
- 去掉审查：模板路径本身安全，审查价值主要体现在模型生成路径与注入错误检出。
## 5. 限制与边界

- 只有 6 个用例，每个变体只运行 1 次，没有重复、方差或置信区间；
- 全部使用 provider=mock，不能代表真实 DeepSeek 的质量差异；
- 去掉审查的干净模板本来就没有问题，价值主要靠注入错误验证；
- 注入测试只覆盖 1 个用例、2 条错误，实际只抓到 1 个问题，不能宣称 100% 检出；
- 路由 12 条标注集由团队自行构造，12/12 不代表泛化准确率，也没有盲测集；
- 没有人工可读性、正确性、帮助度评分；
- 因而这些数字只能支持“在本组用例、Mock 条件下”的流程差异，不能外推为“多 Agent 一定优于单 Agent”。
