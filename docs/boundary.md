# 一页纸边界说明（给评委/答辩用）

## 这是什么

一个本地运行的**多 Agent 健康建议演示平台**：分工、检索、审查、轨迹可解释。它不是医疗器械，不提供诊断或处方。

## 数据哪些是真的、哪些是演示的

| 内容 | 性质 | 说明 |
|---|---|---|
| 178 条中药 / 28 条西药 / 158 条食物 / 25 个心理主题 | **演示数据集** | 人工整理，来源标注为药典/说明书/USDA/中国食物成分表/WHO/NHS，**尚未经执业药师逐条审核** |
| 价格、库存、有效期 | **演示值** | 仅用于展示交互，不代表真实市场 |
| 检索到的网页/说明书 | **真实公开来源** | PubMed、openFDA、NHS/WHO/CDC，页面内容可能随时间变化 |
| 单 Agent vs 多 Agent 实验 | **真实测量** | DeepSeek 模型、4 个用例，见 `docs/experiment.md` |
| 消融实验 | **真实测量** | Mock 模型、6 个用例，见 `docs/ablation.md` |
| 路由准确率 12/12 | **小样本标注** | 12 条人工标注，不是临床评测 |
| 记忆/画像/用药/计划 | **用户本机数据** | 存本地 SQLite；默认 Mock 不外发 |

## 覆盖了什么

- 常见轻症：发热、咽痛、咳嗽、胃胀、失眠、头痛、痛经等；
- 中成药 + 药材 + 备用西药组合推荐，带用法/禁忌/价格区间；
- 红旗症状识别（胸痛、呼吸困难、意识改变等）→ 直接建议就医；
- 孕期/过敏/慢病过滤；常见中西药相互作用（内置规则 + openFDA 说明书）；
- 心理支持与危机资源（12356、400-161-9995 等）；
- 食物检索与图片识别（本地 CLIP）；
- 用药提醒、疗程打卡、库存/有效期、一周康复计划与趋势；
- 断网演示：Mock 模型 + 本地知识库 + 证据缓存。

## 没覆盖什么（被问就直说）

- 不做诊断、不开处方、不调整个体化剂量；
- 不覆盖急危重症院前处置，只做识别与就医建议；
- 知识库不是全量药品库，相互作用"查不到 ≠ 没有"；
- 未接医院 HIS/电子病历/医保；
- 未做临床验证、没有医生签字背书；
- 演示版为单用户本地模式，无账号隔离、无 HTTPS、SQLite 不加密；
- 提醒跨设备依赖浏览器推送服务可达性（FCM 在部分网络不可用）。

## 不能说的三句话

1. ❌"这个建议经过药师审核"——目前没有；
2. ❌"能替代医生/能诊断"——不做诊断；
3. ❌"引用 100% 正确"——引用可核验率指"正文引用能在来源清单里找到"，不是"来源结论绝对正确"。

## 答辩速答

**问：和通用大模型有什么区别？**
答：通用模型一次生成；我们是团队分工 + 真实检索 + 审查 + 轨迹。对照实验里引用可核验率 0% → 100%，审查问题 4.25 → 0。

**问：慢 10 倍值吗？**
答：健康场景优先可信；且缓存/并行/Mock 可把重复提问降到 0 ms、演示零 token。

**问：知识库可靠吗？**
答：演示数据集，来源可查但未逐条专业审核；上线前需药师复核，这是明确的后续工作。

**问：出了错谁负责？**
答：平台给的是科普建议，红旗场景强制就医；所有回答带免责声明，审查记录可追溯。
