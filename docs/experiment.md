# 单 Agent vs 多 Agent 对照实验

> 小样本案例研究，不是统计显著性结论。这里的“引用可核验”指编号能回到来源清单，不代表来源原文一定支持该句；支持性需要人工抽检，见文末限制。

- 模型：`deepseek`
- 常规病例：3 个（发烧咽痛、高烧头痛、咳嗽黄痰）
- 急救病例：1 个（胸痛、呼吸困难），走确定性红旗短路，**单独列出，不混入平均**
- 单 Agent：一次模型调用，无工具、无知识库、无审查
- 多 Agent：分诊 → 辨证 → 并行检索 → 中成药知识库 → 报告 → 安全审查

## 常规病例汇总（n=3）

| 指标 | 单 Agent | 多 Agent |
|---|---|---|
| 平均耗时 | 4.74 s | 65.97 s |
| 平均 token | 632.33 | 14,326.33 |
| 编号可回溯率（有来源的用例） | 0% | 100%（3/3 例） |
| 平均审查问题数 | 4.33 | 0 |
| 含免责声明 | 0/3 | 3/3 |
| 红旗场景正确率 | 3/3 | 3/3 |

## 急救病例（n=1）

| 指标 | 单 Agent | 多 Agent |
|---|---|---|
| 耗时 | 7.11 s | **0.00 s** |
| 来源数 | 0 | 0 |
| 行为 | 模型生成回答 | 确定性建议急诊，不进入检索/审查 |
| 红旗提示 | 有 | 有 |

> 急救短路的 0 秒是**安全设计结果**，不是“多 Agent 更快”；不能拿它和常规病例平均。

## 逐例（常规 3 例）

| 用例 | 症状 | 单:耗时/可回溯/审查问题 | 多:耗时/可回溯/审查问题/证据数 |
|---|---|---|---|
| fever-sore-throat | 发烧，咽喉痛，有点怕冷 | 4.41s / 0% / 3 | 46.91s / 100% / 0 / 5 |
| high-fever | 高烧39度，头痛 | 4.96s / 0% / 4 | 49.81s / 100% / 0 / 8 |
| cough-phlegm | 咳嗽三天，有黄痰 | 4.84s / 0% / 6 | 101.19s / 100% / 0 / 10 |

## 结论边界

1. 多 Agent 的收益是**可回溯、审查问题少、固定免责声明**，代价是约 14 倍耗时和约 23 倍 token。
2. 单 Agent 基线是“裸模型”，**不是工具增强单 Agent**；它没有来源，因此 0% 引用可回溯率有指标构造偏差，不能单独作为“多 Agent 更正确”的证据。
3. 审查问题由平台同一套规则计算，多 Agent 已经按该规则修复过；存在自评偏差。应补独立审查或人工抽检。
4. 小样本、单次运行，未报告方差、置信区间和模型版本/温度；结论只能作为案例研究，不能外推。
5. 下一步应补：工具增强单 Agent 基线、常规/急救分层、3 次重复、来源支持性人工抽检、独立评估者、多 Agent 失败案例。
